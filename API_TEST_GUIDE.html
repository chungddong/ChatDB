📋 ChatDB API 테스트 가이드

📌 테스트 환경 정보
• Base URL: http://studyswh.synology.me:41847
• Swagger UI: http://studyswh.synology.me:41847/swagger-ui/index.html#/
⚠️ 주의사항
  • 테스트는 반드시 순서대로 진행해야 합니다.
  • 각 단계에서 받은 ID와 토큰을 메모하여 다음 단계에서 사용하세요.
  • JWT 토큰은 로그인 시 받으며, 이후 대부분의 API 요청에 필요합니다.
  • 토큰은 Authorization 헤더에 Bearer {token} 형식으로 전달합니다.

1. 인증 (Authentication) API 테스트

1회원가입 - 사용자 A

POST /api/auth/register

요청 본문:

{
  "email": "user_a@example.com",
  "username": "UserA",
  "password": "password123",
  "profileImage": "https://example.com/profile_a.jpg"
}

예상 응답:

{
  "success": true,
  "message": "회원가입이 완료되었습니다.",
  "user": {
    "id": 1,
    "email": "user_a@example.com",
    "username": "UserA",
    "profileImage": "https://example.com/profile_a.jpg",
    "createdAt": "2025-10-27T10:00:00"
  }
}
💾 저장할 정보: user_a_id = 1

2. 친구 (Friendship) API 테스트

🔑 인증 필수
이후 모든 API 요청에는 Authorization 헤더가 필요합니다.
형식: Bearer {token}

7친구 요청 보내기 (A → B)

POST /api/friends/request

헤더:

Authorization: Bearer {token_a}

요청 본문:

{
  "friendEmail": "user_b@example.com"
}

예상 응답:

{
  "success": true,
  "message": "친구 요청을 보냈습니다.",
  "requestId": 1
}
💾 저장할 정보: request_id_ab = 1

8친구 요청 보내기 (A → C)

POST /api/friends/request

헤더:

Authorization: Bearer {token_a}

요청 본문:

{
  "friendEmail": "user_c@example.com"

💾 저장할 정보: request_id_ac = 2

4. 메시지 (Message) API 테스트

📢 WebSocket vs REST API
메시지 전송은 두 가지 방법이 있습니다:
• WebSocket: 실시간 채팅 (권장)
• REST API: 메시지 이력 조회, 수정, 삭제

23메시지 전송 (REST API)

POST /api/messages/chatrooms/{chatroomId}

헤더:

Authorization: Bearer {token_a}

URL 파라미터:

chatroomId = 2  (chatroom_id_2 - 그룹 채팅방)

요청 본문:

{
  "content": "안녕하세요! 첫 번째 메시지입니다.",
  "messageType": "TEXT"
}

예상 응답:

{
  "success": true,
  "message": "메시지를 전송했습니다.",
  "data": {
    "messageId": 1,
    "chatroomId": 2,
    "senderId": 1,
    "senderUsername": "UserA",
    "content": "안녕하세요! 첫 번째 메시지입니다.",
    "messageType": "TEXT",
    "sendAt": "2025-10-27T10:30:00"
  }
}
💾 저장할 정보: message_id_1 = 1

      "messageId": 1,
      "content": "수정된 메시지입니다. 안녕하세요!",
      ...
    },
    {
      "messageId": 3,
      "content": "반갑습니다! UserC입니다.",
      ...
    }
  ],
  "count": 2
}
✅ 확인: UserB의 메시지(ID=2)가 삭제되어 2개만 남았습니다.

5. WebSocket 실시간 채팅 테스트

⚠️ WebSocket 테스트 준비
WebSocket 테스트는 JavaScript 클라이언트 또는 전용 WebSocket 클라이언트가 필요합니다.
아래는 브라우저 콘솔에서 테스트할 수 있는 JavaScript 코드입니다.

36WebSocket 연결 및 메시지 전송 테스트

1. SockJS 및 STOMP 라이브러리 로드:

<script src="https://cdn.jsdelivr.net/npm/sockjs-client@1/dist/sockjs.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@stomp/stompjs@5/bundles/stomp.umd.min.js"></script>

2. WebSocket 연결 코드:

// WebSocket 연결 설정
const socket = new SockJS('http://studyswh.synology.me:41847/ws');
const stompClient = Stomp.over(socket);

// 연결
stompClient.connect({}, function(frame) {
    console.log('Connected: ' + frame);
    
    // 채팅방 구독 (chatroomId = 2)
    stompClient.subscribe('/topic/chatroom/2', function(message) {
        console.log('받은 메시지:', JSON.parse(message.body));
    });
    
    // 메시지 전송
    stompClient.send("/app/chat/2/send", {}, JSON.stringify({
        'content': 'WebSocket 테스트 메시지입니다!',
        'messageType': 'TEXT'
    }));
});

3. 읽음 처리 전송:

// 메시지 읽음 처리
stompClient.send("/app/chat/2/read", {}, JSON.stringify({}));
WebSocket 엔드포인트:
• 연결: ws://studyswh.synology.me:41847/ws
• 메시지 전송: /app/chat/{chatroomId}/send
• 읽음 처리: /app/chat/{chatroomId}/read
• 구독 (받기): /topic/chatroom/{chatroomId}

6. Swagger UI 사용법

1단계: Swagger UI 접속
브라우저에서 http://localhost:8080/swagger-ui/index.html 접속
2단계: API 선택
테스트하고 싶은 API 카테고리(Auth, Friendship, ChatRoom)를 펼침
3단계: 요청 실행
• Try it out 버튼 클릭
• 요청 본문(Request body) 입력
• Execute 버튼 클릭
4단계: JWT 토큰 설정 (인증이 필요한 API의 경우)
• 페이지 상단의 Authorize 버튼 클릭
• Bearer 토큰 입력: Bearer {로그인 시 받은 token}
• Authorize 버튼 클릭하여 저장
💡 팁
  • 응답의 id, requestId, token 등은 메모장에 복사해두세요.
  • 각 테스트 단계에서 받은 값을 다음 단계에서 사용합니다.
  • Swagger UI의 Schemas 섹션에서 각 DTO 구조를 확인할 수 있습니다.
